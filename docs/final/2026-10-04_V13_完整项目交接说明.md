# 2026-10-04｜V13 Mag 7 Earnings Radar 完整项目交接说明

## 一、项目目标

建立一个可公开访问、自动更新、可审计的 Mag 7 财报日历与研究页面。系统必须明确区分事实、预测和模型表达，不能把市场预计写成公司确认，也不能提前生成财报后的结论。

## 二、当前状态

- 公司：MSFT、AAPL、GOOGL、AMZN、NVDA、META、TSLA。
- 历史覆盖：2024 年以来 77 场已发布财报，每家公司 11 场。
- 未来覆盖：当前 28 条事件，每家公司 4 条；预计与推算状态明确区分。
- 研究覆盖：77 场历史 Preview / Analysis；28 条未来事件均有结构化 Preview。
- 行情：QQQ 与 Mag 7 日线，展示财报后 1 日和 5 日相对表现。
- 宏观：已公布的 FOMC、CPI、非农和 PCE。
- 自动化：GitHub Actions 更新数据、运行测试并部署 GitHub Pages。
- 当前测试：30 项契约测试。

## 三、架构

```text
Nasdaq ───────────────> sync_mag7_calendar.py ─> mag7.json / us_earnings_candidates.json
Yahoo Finance ────────> sync_market_data.py ───> market_qqq.json
宏观公开数据 ─────────> sync_macro_events.py ──> macro_events.json
公司 IR + 可选 Paratera > sync_msft_research.py -> msft_research.json
日历 + EPS + 行情 + 深度样本
                      > sync_mag7_research.py ──> mag7_research.json
静态 JSON ─────────────────────────────────────> calendar.html ─> GitHub Pages
```

浏览器不保存密钥，也不直接调用模型。公开 JSON 是静态站点的数据层。

## 四、AI 与确定性逻辑边界

确定性程序负责日期、状态、EPS、收益率、来源、缓存、测试和发布。AI 只允许在已经核验的证据范围内压缩文字；它不能新增数字、改变日期、创造来源或决定事件状态。

日常全量研究为确定性生成，LLM 调用数为 0。Microsoft 深度研究可以按需使用 Paratera 压缩表述，但存在调用上限和数字校验。

## 五、V13 主要变化

- 所有 28 条未来 Mag 7 事件都有详细 Preview，不再只有 Microsoft。
- 历史验证收敛为自动更新证据与固定快照，不再展示无效选择区。
- Preview / Analysis 的风险区只展示投资风险和来源，隐藏内部验证框架。
- 自动更新验证台展示实际快照、上游检查、内容变化、独立真实探针和 Actions 链接。
- 页头、系统说明、来源链接、今日标记和整体视觉层级完成统一。
- 文档按 V13 当前交付与 V1–V12 过程归档重新整理。

## 六、关键约束

1. 不要随意修改 `frontend/data/`、`backend/` 和 workflow 中的稳定路径。
2. `confirmed` 只能来自公司 IR；`estimated` 和 `projected` 不能自动升级为确认。
3. 未来事件只生成 Preview；正式结果出现后才允许生成 Analysis。
4. 数据缺失时显示不可得，不用模型补齐。
5. 修改后先运行全部测试，再提交和部署。
6. GitHub schedule 可能延迟；页面应展示实际运行时间，不把目标时间当成完成时间。

## 七、继续开发的建议顺序

1. 查看 `git status` 与最近提交。
2. 阅读根目录 `README.md`、`VERSION.json` 和本交接文件。
3. 运行 `python -m unittest discover -s tests -v`。
4. 重点阅读 `backend/sync_mag7_research.py` 与 `frontend/calendar.html`。
5. 修改后验证数据契约、前端脚本和 Pages 部署结果。

## 八、已知限制

- 除 Microsoft 深度样本外，研究主要基于 EPS、行情和公司特定观察框架，尚未逐季抽取全部收入、分部及指引。
- 宏观数据源没有可靠共识值时，只展示实际值与前值。
- GitHub Pages 没有用户数据库；自选股只保存在浏览器 localStorage。
- Yahoo、Nasdaq 和宏观聚合接口适合研究 Demo，不提供商业 SLA。
- `calendar.html` 仍是较大的单文件；继续扩展时应拆分数据、状态、组件、图表和研究模块。
