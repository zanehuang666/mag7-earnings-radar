# 2026-10-03｜V3｜分支探索与行情功能交接

## 1. 本分支目标

本分支围绕“财报日期先可验收、再补研究内容”的顺序，对原始 Demo 做可行性探索。主要目标是：

1. 让日历从静态展示变成可点击、可回溯、可验证的财报流程；
2. 覆盖 Mag 7 自 2024-01-01 起的历史事件和未来多期日期；
3. 支持增加、查看和删除非 Mag 7 股票；
4. 在不申请付费财经 API 的情况下验证行情接入；
5. 保持 GitHub Pages 公开访问和 GitHub Actions 自动更新。

公开页面：<https://zanehuang666.github.io/mag7-earnings-radar/calendar.html>

## 2. 主要尝试与结果

| 尝试 | 结果 | 关键判断 |
|---|---|---|
| Nasdaq 每日 earnings calendar | 可用 | 适合获取未来约 120 天市场预计日期，但不是完整股票代码库 |
| Nasdaq earnings-surprise | 可用 | 可自动校准最近四次已发布财报日期及 EPS surprise |
| 公司 IR 确认层 | 已预留 | 只有 IR 正式公告才可标记为 `confirmed`，当前不自动伪造确认状态 |
| 历史节奏推算 | 可用 | 当市场日历尚未给出后续季度时，按历史季度节奏推算，并明确标记为低置信度 `projected` 和 ±7 天区间 |
| 浏览器直接请求 Nasdaq/Yahoo | 不适合 | CORS 和稳定性不足，公开静态页面不应直接依赖第三方接口 |
| Stooq 免密钥日线 | 未采用 | 实测触发反机器人页面，不适合作为自动任务来源 |
| Nasdaq 历史行情接口 | 未采用 | 实测没有返回可用历史行 |
| Yahoo Chart 服务端抓取 | 已采用 | 无需 API key，可由 GitHub Actions 抓取并缓存；适合笔试 Demo，但没有正式 SLA |
| QQQ 与 Mag 7 对比 | 已完成 | 八条日线统一以 2024 年首个交易日归一为 100，解决绝对股价尺度不可比的问题 |

## 3. 已完成的主要修改

### 3.1 财报日历与验证流程

- 日历中的每个日期均可点击；有事件时可继续进入 Preview / Analysis。
- 正式模式展示 2024-01-01 以来的历史财报和未来日期。
- 历史验证模式支持模拟时间，并显示“未发布 → 发布日 → 已发布”的状态变化。
- Mag 7 公司按钮可打开该公司的完整历史与未来财报列表。
- 增加返回、关闭、月份跳转、2024 起点和下一次预计等操作。
- 每家公司保留四期未来事件，日期层级为：
  - `projected`：历史节奏推算；
  - `estimated`：Nasdaq 市场日历预计；
  - `confirmed`：公司 IR 正式确认；
  - `reported`：已经发布。

### 3.2 自选股搜索与 MU 修复

- 页面可输入股票代码加入自选股；记录保存在浏览器 `localStorage`。
- Mag 7 使用绿色 `M7` 标签且不可删除；新增股票使用紫色 `自选` 标签，可点击 `×` 删除。
- 原搜索索引只来自未来 120 天 Nasdaq 日历，因此刚发布财报、下一期尚未进入日历的 MU 无法命中。
- 修复后采用双层索引：
  1. 未来 120 天 Nasdaq 日历；
  2. 明确支持股票的“Nasdaq 历史记录 + 确定性节奏推算”档案。
- MU 目前包含最近四次真实已发布日期，以及四期低置信度未来推算。
- 该机制仍不是完整的全美股证券主数据库；没有未来日历记录、也未配置历史档案的代码仍可能无法加入。

### 3.3 行情与财报事件图

- 接入 QQQ、MSFT、AAPL、GOOGL、AMZN、NVDA、META、TSLA 日线。
- 数据由 GitHub Actions 服务端获取，页面只读取仓库内的静态 JSON，避免浏览器跨域问题。
- 未选择公司时，QQQ 清晰显示，七只个股半透明显示。
- 选择 Mag 7 公司后，只突出该公司与 QQQ，便于比较相对表现。
- 财报圆点放在对应公司的股价表现线上，而不是统一放在 QQQ 线上。
- 自定义悬浮卡片展示：
  - 公司和财报日期；
  - 当日真实美元收盘价；
  - 2024 年至该日的区间涨跌；
  - 相对 QQQ 的百分点差；
  - EPS 高于/低于一致预期或“结果未结构化”。
- 图表只用于观察时间关系和市场环境，不把相关性解释为因果关系。

## 4. 自动更新机制

工作流：`.github/workflows/sync-and-deploy.yml`

- 工作日北京时间约 09:37、21:37 各运行一次；
- 同步财报日期、搜索候选索引和八条行情序列；
- 运行数据契约测试；
- 提交新的静态数据快照；
- 自动部署 GitHub Pages。

行情不是实时数据。北京时间上午运行通常可取得美股前一交易日较完整的收盘数据；晚间运行主要用于刷新财报日期等状态。行情源暂时不可用时，脚本保留上一份有效快照，避免公开页面失效。

## 7. 调试经验

- 本机普通执行器曾出现 `setup refresh had errors`；授权执行可用，说明问题来自 Codex 桌面端执行器刷新，而非代码、Git 或中文路径。
- Git HTTPS 曾发生短暂连接重置；使用仓库级一次性 HTTP/1.1 推送后恢复。
- 自动工作流可能在本地编辑期间提交新数据，导致 push 被拒绝。正确处理方式是先 fetch/rebase，再用同步脚本重新生成冲突的派生 JSON；不应强推覆盖远端。
- Windows 无界面 Edge 可用于真实页面渲染验收；源代码还通过 JavaScript 解析检查和 Python 数据契约测试。

## 8. 尚未完成与主分支建议

1. Preview / Analysis 目前仍以省 token 模板为主，尚未系统接入原始财报、电话会、卖方一致预期与多来源引用。
2. 搜索不是完整证券主数据库。若希望任意美股代码都可加入，建议增加轻量 ticker master，并为用户 watchlist 在服务端按需生成历史/预测档案。
3. Yahoo Chart 属于非正式免密钥来源，适合 Demo，不适合有 SLA 要求的正式产品；后续可在不改前端 JSON 契约的情况下替换为授权行情源。
4. 当前行情只覆盖 Mag 7，MU 等自选股尚未自动加入行情图。可把自选列表改为服务端 watchlist 后按需抓取，但需考虑静态 Pages 无后端状态的问题。
5. 建议下一阶段优先完善 Preview / Analysis 的研究质量、引用和可复现性，而不是继续增加页面功能。

## 9. 可复用的设计结论

- 日期、状态迁移、去重、置信等级和定时更新应由确定性逻辑控制；
- LLM 适合摘要、解释和研究框架，不适合决定财报是否确认或捏造缺失日期；
- 第三方接口先在服务端缓存为稳定契约，再由静态前端读取；
- 所有推算必须显式展示置信等级、方法和范围；
- 自动生成数据发生 Git 冲突时应重新生成，而不是人工合并大型 JSON。
