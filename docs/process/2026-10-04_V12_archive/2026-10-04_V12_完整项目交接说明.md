# 2026-10-04｜V12｜Mag 7 Earnings Radar 完整项目交接说明

> 用途：提供给新的 Codex/GPT 对话作为前置上下文。请先读本文件，再读根目录 `README.md` 和 `tests/test_contract.py`，不要从头重建项目。

## 一、最初的笔试任务

笔试要求构建一个可实际操作的美股 Mag 7 财报跟踪网页，核心是：

1. 清楚展示七家公司预计或确认的财报日期；
2. 财报前一天生成 Preview；
3. 财报发布后生成 Analysis，判断整体偏超预期还是不及预期并解释原因；
4. 可以使用历史事件、模拟时间或 mock 数据验证完整流程；
5. 重点考察需求拆解、AI 与确定性逻辑的边界、系统可维护性、失败定位和迭代能力；
6. 最终需要网页、简短项目说明和可答辩的系统设计。

后续用户逐步增加了真实日期、自动更新、自选股、行情、宏观事件、历史模拟、专业研究、来源和公开访问等要求。用户明确不希望使用昂贵的 FMP，也不希望大规模人工维护；允许使用 Paratera/DeepSeek-V4-Flash，但要求节省 token。

## 二、用户要求的演进

### 阶段 1：可运行小模板

- 先做可运行 Demo，不追求复杂 UI；
- 前后端逻辑分离；

- Paratera 地址为 `https://llmapi.paratera.com`，模型为 `DeepSeek-V4-Flash`，密钥放 GitHub Secrets，不能写入仓库。

### 阶段 3：完整日历与交互

- 每个日期、公司和事件可点击；
- 正式日历从 2024-01-01 起覆盖全部 Mag 7 历史财报；

- 公司面板可返回/关闭；
- 输入股票代码加入自选股，Mag 7 不可删除，自选股可删除；
- MU 需要在未来日历缺失时使用历史节奏推算。

### 阶段 4：行情与研究

- QQQ 和 Mag 7 股价归一化展示；
- 财报节点放到对应公司价格线上；
- 未选择公司时其他个股半透明，选择后突出该股与 QQQ；
- 研究结论颜色只能来自结构化完整 Analysis，不能用单项 EPS 冒充整体判断；
- Microsoft 先做三期深度样本：2026-01-28、2026-07-29、2026-11-04；
- Preview/Analysis 需要指标表格、来源、核心观察、指引变化、相对 QQQ 表现和专业风险框架。

### 阶段 5：自动更新与历史模拟

- 页面显示真实快照时间和短期真实验证样本 AEHR；
- 历史验证需整体推进系统时间，而非简单换一段文字；
- Microsoft FY26 Q2 被固定为双快照案例：T-1 只能 Preview，T+1 出现实际指标和 Analysis；
- 正式日历加入已公布的 FOMC、CPI、非农和 PCE，未来宏观预测不进入页面。

### 阶段 6：V12 收口

- Microsoft 三期研究结构推广至全部 Mag 7 2024 年以来 77 场财报；
- 不允许日常更新反复消耗 LLM；
- 整理最终文件和过程文件；
- 编写最终 README 和本交接文件。

## 三、当前实现结果

### 1. 正式日历

- 7 家公司：MSFT、AAPL、GOOGL、AMZN、NVDA、META、TSLA；
- 2024-01-01 至今共 77 场已发布财报，每家公司 11 场；
- 每家公司另外显示 4 期未来事件：通常 1 期 Nasdaq `estimated` + 3 期历史节奏 `projected`；
- `confirmed` 只允许公司 IR 正式公告写入，系统不会把市场预计自动升级为确认；
- 每个日期、公司和事件均可点击。

### 2. 全量 Preview / Analysis

`frontend/data/mag7_research.json` 是 V12 统一研究层：

- 77 场历史财报全部有 Preview 和 Analysis；
- 每场都有 EPS consensus、actual、surprise、分析师样本、业务观察点、市场关注、专业风险；
- 每场都有随后 1 日/5 日个股相对 QQQ 表现；
- 综合结论不只看 EPS：EPS 和次日相对价格同向才判为偏正面/偏负面，否则为 mixed；
- 当前分布约为 28 positive、8 negative、41 mixed，具体以 JSON 为准；
- 所有基线研究由确定性模板生成，0 LLM 调用；
- 已成熟记录按事件 ID 缓存。日常工作流只处理新报告事件；若新事件尚未形成完整 5 个交易日行情窗口，只重复补算这一条，成熟历史直接保留；
- Microsoft 两个历史深度样本覆盖普通模板；Microsoft 未来样本也保留在统一文件中。

重要边界：除 Microsoft 深度样本外，全量基线主要有 EPS 和价格数据，没有自动宣称收入、分部和管理层指引已经被完整解析。页面明确提示回到 IR 原始材料复核。

### 3. Microsoft 深度研究

`frontend/data/msft_research.json` 包含：

- `msft-2026-01-28`：过往已发布样本；
- `msft-2026-07-29`：最近已发布样本；
- `msft-2026-11-04`：未来预计样本，IR 尚未确认。

历史样本包含收入、调整后 EPS、Azure、云毛利率、CapEx、指引变化、MSFT 相对 QQQ 反应和投资风险传导框架。模型只能压缩已经核验的 verdict/summary，不能改数字或新增来源；若输出出现证据中没有的数字会被拒绝。

### 4. 历史时间模拟

- 初始系统时间：2026-01-27 18:00 ET；
- 事件：Microsoft FY26 Q2，财报日 2026-01-28；
- 快照 A：waiting release，只能看 Preview；
- 点击按钮后系统推进到 2026-01-29 09:00 ET；
- 快照 B：reported，写入 Revenue、EPS、Azure 等实际结果并开放 Analysis；
- 两张快照和差异列表同时展示，重复运行不消耗 token。

### 5. 行情

- `backend/sync_market_data.py` 免 API key 抓取并缓存 QQQ 和 Mag 7 日线；
- 页面以 2024 年首个交易日归一为 100；
- 财报节点位于对应公司的股价线上；
- 研究结论色：绿色 positive、红色 negative、橙色 mixed、空心灰为无完整研究；
- V12 后全部 77 场历史事件都有结构化研究颜色；
- 市场反应只是交叉验证，不能直接证明财报导致股价变化。

### 6. 宏观事件

- FOMC/联邦基金目标区间、CPI、非农、PCE；
- 只收录已公布且有 actual 的事件；
- 免费 XOOMAR 聚合层提供 actual/previous，但不提供可靠 consensus；
- 页面明确写“市场一致预期不可得”，只做 actual vs previous，绝不把 previous 当作 consensus；
- 当前免费接口历史大约六个月，后续 Actions 会持续生成新快照。

### 7. 自选股

- 浏览器输入 ticker，从 Actions 生成的候选索引中加入；
- 自选保存在浏览器 `localStorage`，不是跨设备账户数据；
- Mag 7 有绿色 M7 标签且不可删除，自选股为紫色且可删除；
- MU 有专门的历史档案 + 四期节奏推算；
- 自选股目前只有日期和省 token 简版研究，没有全量 Mag 7 深度研究。

## 四、系统架构和数据流

```text
Nasdaq 日历/Surprise ──> sync_mag7_calendar.py ──> mag7.json
                         └──────────────────────> us_earnings_candidates.json

Yahoo 行情快照 ─────────> sync_market_data.py ──> market_qqq.json

XOOMAR + 官方链接 ───────> sync_macro_events.py ─> macro_events.json

公司 IR/正式材料 + 可选 Paratera
                         └> sync_msft_research.py -> msft_research.json

mag7.json + Nasdaq 历史 EPS + market_qqq.json + msft_research.json
                         └> sync_mag7_research.py -> mag7_research.json

上述静态 JSON ──────────> calendar.html ─────────> GitHub Pages
```

GitHub Actions 顺序：同步日期 → 同步行情 → 同步宏观 → 更新 Microsoft 深度层 → 更新全量增量研究 → 契约测试 → 提交 `frontend/data/` → 发布 Pages。

## 五、AI 与确定性逻辑的边界

### 交给确定性逻辑

- 日期状态和四级状态转换；
- 历史事件覆盖与未来季度节奏；
- EPS 实际/共识差值；
- 1 日/5 日相对 QQQ 收益；
- 宏观 actual/previous 比较；
- 历史时间推进；
- 引用、schema、缓存、测试和发布；
- 全量 77 场基线研究。

理由：这些结果可以计算、验证和回归测试，不应由模型猜测。

### 可交给模型

- 在已有证据范围内压缩复杂观点；
- 将核验后的事实组织成更简洁的 verdict/summary；
- 未来扩展时对电话会文本做主题归纳。

模型不能决定发布日期、不能修改数字、不能虚构来源、不能把 Preview 写入事后信息。当前 Microsoft 深度脚本设置了调用数量、事件 ID、输出 token 和数字白名单约束。

## 六、数据来源与准确性边界

- 财报日期与 EPS：Nasdaq 公开日历和公司 earnings-surprise；
- 确认日期：各公司 Investor Relations；
- 行情：Yahoo Finance 缓存快照，适合 Demo，不提供正式 SLA；
- 宏观：XOOMAR 聚合，逐项链接 BLS、BEA、Federal Reserve/FRED；
- 深度 Microsoft：公司 press release、earnings call、AP/FactSet 共识和行情。

准确性原则：来源不可得时显示不可得，不用 LLM 补写。`estimated` 和 `projected` 不是公司确认日期。

## 七、自动更新与已知调度问题

目标 cron：

- 工作日 09:37、21:37（北京时间）；
- 周末 09:37（北京时间）。

GitHub Actions schedule 不是精确任务调度器。实测曾出现：目标 09:37，实际 10:27 才创建运行；目标 21:37，实际约 21:51。GitHub 官方说明 scheduled run 会因负载延迟，极端情况下可能丢弃。

页面展示的快照时间是真实 `generated_at`，不是 cron 目标时间。若下一版本增强，建议：

1. 增加一个提前 30 分钟的冗余 cron；
2. 数据中写入 `GITHUB_RUN_ID`、计划时间、实际开始时间、完成时间和触发类型；
3. UI 把“自动频率”改成“目标触发时间”；
4. 若业务要求准点，改用外部调度器，而不是依赖 GitHub schedule。

## 八、主要 Debug 记录

### 1. Codex 执行器刷新故障

症状：普通命令在创建子进程前报 `setup refresh had errors`，但授权执行可运行 PowerShell/Git/gh。Codex 桌面更新状态曾为 `restart_required`。

结论：是桌面端沙箱/执行器初始化问题，不是 Python、Git、中文路径或项目代码。重启应用后恢复。详细过程已归档在 `docs/process/2026-10-01_V1_执行器错误报告.md`。

### 2. Git HTTPS 临时连接重置

症状：`git push` 出现 connection reset/443 timeout，但 `api.github.com` 或稍后 `ls-remote` 正常。

结论：临时网络通道抖动。有效做法是 `git -c http.version=HTTP/1.1 push`，先只读握手、低频重试。曾尝试 SSH 备用，但账户 token 缺少 `admin:public_key`；没有添加 deploy key，临时密钥已经删除，远端保持 HTTPS。

### 3. Paratera 返回结构问题

模型有时把 JSON 放在 `reasoning_content` 或在 JSON 前加简短文字。脚本现在兼容严格 JSON、fence JSON 和简短前缀，同时仍执行字段和数字校验。模型失败不会覆盖已核验快照。

### 4. 研究颜色误用

早期图表把某些单项 EPS surprise 当作完整超预期判断，导致其他公司也出现结论颜色。后来改为只有存在 `research.analysis.result_tone` 才着色。V12 中全量研究显式使用 EPS + 相对价格复合规则，因此每个颜色都有结构化依据。

### 5. 时间模拟逻辑错误

早期历史模式对所有 `reported` 事件直接打开 Analysis，没有尊重模拟日期。已修正为 `stageFor(event)` 根据全局模拟时间决定 Preview/release/aftercheck，并加入 A/B 快照。

### 6. 全量研究首次聚合失败

Microsoft 深度事件依赖文件级 ticker，没有在事件内重复 `ticker`，新聚合器排序时报 `KeyError: ticker`。解决方法是在聚合边界补齐 `ticker=MSFT`、`company=Microsoft`，不修改原深度文件。

### 7. NVIDIA 单季数据源差异

Nasdaq 某历史日历行缺少 EPS forecast，而公司 earnings-surprise 表存在更完整的近期口径。V12 规定：最近季度优先使用 company earnings-surprise，较早季度使用 daily calendar，并用测试确保 77 场都有实际 EPS 和预期。

## 十、当前仍未完全完成或可以继续提升的部分

1. 除 Microsoft 外，77 场基线尚未逐季解析收入、分部、正式管理层指引和电话会；当前有真实 EPS、价格和公司级研究框架，但不是 77 份人工深度报告。
2. 宏观免费源没有市场 consensus，无法判断真正的数据 surprise，只能比较前值。
3. 自选股研究没有自动升级到 Mag 7 同等深度。
4. GitHub schedule 不保证准点，需要冗余计划或外部调度。
5. 静态站点没有真正的用户数据库；JSON 仓库是公开数据存储，localStorage 只保存单浏览器自选股。
6. Yahoo/XOOMAR/Nasdaq 均为免密钥 Demo 数据链，适合笔试，不是商业 SLA。
7. UI 文件是单个较长 HTML。若继续扩大，应拆成 `data/`, `state/`, `components/`, `charts/`, `research/` 模块并引入轻量构建流程。

## 十二、用户偏好和协作方式

- 用户偏好先给方案，再实现，再演示/debug，再更新方案；
- 不希望频繁等待确认，允许在范围内自主推进；
