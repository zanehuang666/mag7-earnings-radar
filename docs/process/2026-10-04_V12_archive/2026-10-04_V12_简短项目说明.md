# Mag 7 Earnings Radar：简短项目说明

版本：2026-10-04｜V12

## 1. 系统怎么工作

系统的数据流是：

**公开数据源 → Python 同步与校验 → 静态 JSON → 网页展示。**

1. Nasdaq 提供财报日期、EPS 预期和实际结果；公司 IR 用于确认日期和核对正式材料；Yahoo Finance 提供个股与 QQQ 行情；宏观接口提供已经公布的 CPI、非农、PCE 和利率数据。
2. Python 脚本把不同来源统一成同一套公司、日期、指标、来源和状态结构。日期被明确分为“节奏推算、市场预计、IR 确认、已发布”。
3. 程序计算 EPS 预期差、财报后个股相对 QQQ 的 1 日和 5 日表现，并为 2024 年以来 77 场 Mag 7 财报生成结构化 Preview 和 Analysis。
4. 自动测试检查公司和历史覆盖、数字、来源、状态转换及页面契约。测试通过后，GitHub Actions 更新数据并发布 GitHub Pages。
5. 浏览器只读取已经生成的 JSON，不保存 API 密钥，也不会在用户打开页面时临时编造研究结果。

AI 只用于少量深度研究：它在已经核验的数字和来源范围内压缩文字。常规日历、行情、宏观数据和 77 场基础研究都不依赖 AI；已有研究会被缓存，日常更新不会反复消耗 token。

## 2. AI 与确定性逻辑如何分工

### 交给确定性逻辑

- 财报日期、状态和模拟时间推进；
- EPS 实际值、预期值及差值；
- 个股与 QQQ 的收益计算；
- 来源引用、缓存、自动发布和回归测试；
- 判断数据是否齐全，以及是否允许生成 Analysis。

这些工作有明确答案，必须可重复、可测试、可追溯。交给模型容易造成日期错误、数字失真，或者在财报发布前提前写出事后结论。

### 交给 AI

- 在固定证据范围内压缩长材料；
- 把多个已知事实整理成简洁摘要；
- 帮助表达风险、分歧和后续观察问题。

AI 不决定日期，不修改数字，不创造来源。模型输出如果增加证据中不存在的数字，会被程序拒绝。这个分工让模型负责语言，程序负责事实，同时降低成本和失败范围。

## 3. 如何继续扩展而不失控

后续扩展会继续保持五层边界：

- **数据连接层**：Nasdaq、公司 IR、行情、宏观和原始财报分别接入；
- **统一数据层**：所有公司共用事件、指标、来源和状态结构；
- **研究流程层**：Preview、Analysis、风险检查和 AI 摘要相互独立；
- **展示层**：日历、公司列表、图表和研究卡片只消费统一数据；
- **验证层**：每增加公司、指标或研究步骤，先增加数据契约和回归测试。

原始财报会作为只读证据保存；多轮追问放在独立会话层，不能直接改写基础事实。新增 AI 能力必须接受固定输入和输出结构，并通过数字、来源和时间边界校验。

核心原则是：**先定义数据和边界，再增加功能；先让结果可验证，再让表达更智能。**

## A. 一个典型 Bug

早期历史验证中，只要事件在现实中已经发布，页面就默认打开 Analysis，即使模拟系统时间仍停在财报前一天。这使“历史重放”看起来能运行，但实际泄露了未来信息。

问题不在文案，而在状态判断同时使用了“现实状态”和“模拟状态”。修复后，所有历史页面统一通过全局模拟时间判断阶段：T-1 只能查看 Preview，发布日显示 release，T+1 才开放 Analysis；同时保留前后两个系统快照，并增加契约测试。

## B. 一次重要的实现调整

项目早期更像单页 Demo，研究内容和页面逻辑结合较紧，也容易把 AI 当作通用补全工具。后来改成：

**确定性数据流水线 + 静态研究缓存 + 可选 AI 表达。**

这次调整减少了随时生成文字的灵活性，但换来了三个更重要的结果：历史数字不会被模型改写；自动更新只处理新增事件；任何问题都能定位到数据源、计算、研究或展示中的具体一层。这也是系统最终被做成现在这种形态的主要原因。
